# tests/api — black-box API suite

**Owner:** QA (`[QA]`). **Language:** Python (uv workspace member `studio-api-tests`).
Strategy: [docs/process/test-strategy.md](../../docs/process/test-strategy.md) §2–§5. Story: TC-30.

These tests start the **real backend as a subprocess** and talk to it only through its public contract: the
command line, the stdout handshake line, stderr log lines, HTTP and (from TC-20) WebSocket. They never import
code from `apps/` or `packages/`; `test_suite_boundaries.py` fails if one does. Developers' unit tests stay next
to their code (`apps/backend/tests`).

## Run

From the repository root (after `uv sync --all-packages`):

```bash
uv run --package studio-api-tests pytest tests/api
```

Useful selections: one story `pytest tests/api -m "ac"` plus `-k`, or grep for the ticket key
(`grep -rn '"TC-17"' tests/api`). Lint and types, from `tests/api/`:

```bash
uv run --package studio-api-tests ruff check .
uv run --package studio-api-tests ruff format --check .
uv run --package studio-api-tests mypy
```

CI runs the same command on Windows and Linux once the pipeline exists (TC-26).

## What the harness gives you (`conftest.py`, `harness/`)

| Fixture / helper | Scope | Use it for |
|---|---|---|
| `backend` | session | Read-only tests. One backend for the whole run, started with `--port 0`. |
| `client` | session | `httpx.Client` for `backend`, with `Authorization: Bearer <token>` once the handshake carries a token (TC-19). |
| `start_backend_fn(args=None, env=None)` | test | Any test that changes state or needs its own settings. Every backend it starts is stopped at teardown. |
| `client_for(bp)` | test | `httpx.Client` for a backend from `start_backend_fn`. |
| `hostile_tmp` | test | A fresh temp dir whose name has a space and non-ASCII characters. |
| `harness.paths.workspace_from_fixture(name, dest)` | — | A temp copy of `tests/fixtures/workspaces/<name>/` (0.2.0+), in a hostile folder. |
| `harness.paths.copy_fixture(rel, dest)` | — | The same for any folder under `tests/fixtures/`. |

`BackendProcess` (returned by both backend fixtures) exposes `handshake` (`port`, `token`, `raw`), `base_url`,
`stdout_lines` (after the handshake), `stderr_lines`, `stderr_json()`, `pids`, `log_path` and `stop()`.

**Process cleanup is checked, not hoped for.** `stop()` kills the whole process tree (on Windows `uv run` makes
`uv` → venv launcher → `python`, and killing `uv` alone orphans the backend), then raises `BackendError` if any of
those processes is still alive. A leaked backend therefore fails the test that leaked it.

**Which backend is started.** The documented dev command,
`uv run --frozen --package studio-backend python -m studio_backend --port 0`, from the repository root. To test
another build, set `STUDIO_API_TEST_BACKEND_CMD` to a JSON array, e.g.
`["C:/path/backend/python/python.exe", "-I", "-B", "-m", "studio_backend"]` (ADR-0005 packaged layout).

**Logs.** Every backend writes its stdout/stderr to `backend-*.log` in pytest's temp directory
(`--basetemp` to choose it). pytest keeps the last runs' temp dirs, so the log of a failed test is still there;
CI uploads them as artefacts (TC-26).

## Conventions (strategy §4–§5)

- **File and test names:** `test_<feature>.py`, `test_<behaviour>_<condition>`.
- **Traceability:** every test that verifies an acceptance criterion has `@pytest.mark.ac("TC-<n>", <k>)`
  (repeat the marker for several). The epic test plan (`docs/qa/<version>-test-plan.md`) names the test.
- **Fixtures are read-only.** Copy them with `copy_fixture` / `workspace_from_fixture`; never write under
  `tests/fixtures/`. Each test works in its own temp dir and, from 0.2.0, its own workspace and
  `STUDIO_SETTINGS_DIR`.
- **Hostile paths by default:** use `hostile_tmp` (or the copy helpers, which already use hostile names).
- **No sleeps.** Wait for a condition with a deadline (poll an endpoint, read a log line); never `time.sleep(n)`
  as a synchronisation.
- **No secrets.** Tokens come from the handshake or are generated by the test.
- **Never skip silently.** A flaky test is quarantined with `@pytest.mark.quarantine("TC-<bug>")` and a Jira Bug
  (strategy §8), not deleted or skipped.
- **Test data layout** lives in `tests/fixtures/` and is indexed in its README (from TC-42).
