# 0.2.0 Workspace & persistence — test plan

Owner: `[QA]`. Epic [TC-2](https://mathsuch63.atlassian.net/browse/TC-2). Strategy: [test-strategy.md](../process/test-strategy.md).
Manual procedures: [manual/workspace.md](manual/workspace.md). Fixtures: [tests/fixtures/README.md](../../tests/fixtures/README.md).
Status: draft, written before the stories start (TC-42). Updated when a story's acceptance criteria change or when a
test lands (TC-43 adds the file/test name to each automated case).

**Levels:** `Unit` (developer suite in the app/package) · `API` (`tests/api/`, black-box) · `E2E` (`tests/e2e/`,
Playwright-Electron) · `CI` (evidence from a GitHub Actions run) · `Insp` (QA reads a document/file and records the
result) · `Manual` (scripted procedure, see the manual file).
**OS:** `W` Windows, `L` Linux, `W+L` both. Automated cases run on both OSes in CI unless noted.
**R** = rerun at every 0.2.0 beta and kept in later regressions.
Every case is executed when its story is in **In Test** and again at the beta regression (cases marked **R**).

Conventions used below: `<ws>` is a per-test temp workspace whose path contains a space and a non-ASCII character
(strategy §5.3), created by copying a fixture from `tests/fixtures/workspaces/`. `fx:<name>` names such a fixture.
`<settings>` is a per-test `STUDIO_SETTINGS_DIR`.

## 4. Open questions (asked in TC-42; answers recorded here)
- **Q1, X2-2 black-box (PO + DEV-A).** In 0.2.0 every real file type is at v1, so no project file can be "older".
  TC-33 proves the mechanism with a synthetic kind at unit level, but TC-43 AC1 asks the API suite for "migration with
  backup from a corpus file". Options: (a) X2-2 is proven at unit level in 0.2.0 and black-box from the first real v2;
  (b) the backend accepts a test-only migration registry through an env var. QA recommends (a): a test-only code
  path in the shipped backend is exactly what the fake-runner rule (strategy §9) warns against.
- **Q2, corpus immutability (DEV-A).** Enforce "samples never edited" by a CI check (any `M` status on the corpus path
  fails) or by review only?
- **Q3, ids from names and odd folders (PO + DEV-A).** What id is derived from `Équipe 7` (transliterate to
  `equipe-7`, or drop to `quipe-7`?), from `日本語` or `!!!` (empty slug), and from `Con` (reserved)? How does the list
  show a folder that is not a valid id (`My Proj/`, created by hand) or a folder without `project.json`: ignored,
  or listed with an error?
- **Q4, watcher-off switch (DEV-A).** T-37-5 needs a documented way to force the fallback in tests (env var or
  setting), since CI runners do support file watching.
- **Q5, serialisation details (DEV-A).** Fixtures assume non-ASCII is written as UTF-8 (not `\u` escapes) and
  timestamps as `YYYY-MM-DDTHH:MM:SSZ`. If TC-32 chooses otherwise, QA regenerates the fixtures.
  Also: is a UTF-8 BOM (old Notepad) accepted on load or reported as `file_invalid`?
